# AI 역할 설계 — 역할 AI · 컬러렌즈 · 사람 (v1)

베를로 OS의 AI 3층 구조 설계. v0(대화 초안) → v1: 웹 리서치로 기능 정의를 교정하고 역할 AI를 상세화.

> **핵심 교정 (v0→v1)**: v0의 "마케팅 AI"(인입 분류·응대·견적)는 실제로 **영업(주로 인사이드 세일즈 방식) + 영업지원**이었다.
> ※ v1.1 교정: 핵심 역할명은 **영업(Sales)**이다. "인사이드 세일즈"는 영업을 원격으로 수행하는 *방식*이지 역할 이름이 아니다 — v1 초안이 영업을 이 용어로 대체해 로스터에서 "영업"이 사라져 보였던 것을 되돌린다.
> 마케팅은 퍼널 최상단의 **수요 창출(demand generation)**로 별개 기능이며, 베를로는 인바운드 반응형 사업이라 현재 거의 가동하지 않는다.

## 0. 기능 정의 (B2B 표준, 리서치 근거)

| 기능 | 위치 | 핵심 | quota | 대면성 |
|---|---|---|---|---|
| **마케팅(Marketing)** | 퍼널 최상단 | 수요·인지 창출, 리드(MQL) 생성 — 콘텐츠·SEO·캠페인·아웃바운드 | X | — |
| **인사이드 세일즈(Inside Sales)** | 판매 모션 | 원격(메일/전화/화상) 판매. 인바운드 자격판정→협상→클로징 | O | 원격 고객대면 |
| **영업지원(Sales Support)** | 딜 뒤받침 | 행정·이네이블먼트. 견적문서·오더·등록서류·CRM 기록 | X | 부분 |
| **세일즈 옵스(Sales Ops)** | 인프라 | 시스템·데이터·프로세스·예측 (본 앱 자체가 이 계층에 해당) | X | — |

- SDR = 인바운드 리드 자격판정(마케팅이 만든 리드를 거른다), BDR = 아웃바운드 콜드 발굴(수요를 만든다), AE = 클로징. SDR/BDR/AE 모두 인사이드 세일즈 모델에 속한다.
- **베를로 현실**: 메일/카톡/전화로 들어오는 문의(총판·파트너·고객發)를 받아 자격판정·견적·조율·클로징 → **인사이드 세일즈**. 통장사본·인감·거래처등록·견적서 발행 등 서류·기록 → **영업지원**. 아웃바운드 발굴·콘텐츠·캠페인(마케팅)은 미가동.

## 1. 3층 구조

```
① 역할 AI   초안을 만든다   (자격판정·견적·제안·구축·정산)
② 컬러렌즈  회의적으로 검증  (5색, 사람에게 가기 전 관문 — "회의적 기계")
③ 사람      결정한다        (현재=Claude 대역, 향후=사장님) → 결정이 학습(DomainMemory)
```
흐름: **인입 → 역할 AI 초안 → 컬러렌즈 검증 → 사람 결정 → 학습**

## 2. 채널 구조 (베를로 관점, 딜 단위 역할 태그)

```
Sangfor(벤더) → 총판(상위 공급) → 베를로 → 파트너/SI(하위 채널) → 고객(최종)
                   예: 넥시아스                    예: 두올테크·제이앤지·엔클라우드24   예: 롯데건설·인카금융·씨젠
```
- 베를로 마진 = 매출가(파트너/고객向) − 매입가(총판/벤더發). **영업·CFO AI가 이 채널 위치를 알아야 마진을 옳게 계산.**
- 한 회사가 딜마다 역할이 다를 수 있어 **역할은 엔티티 고정이 아니라 딜 단위 태그**.

## 3. 역할 AI 상세

각 역할 AI 스펙: 정의 · 트리거 · 하는 일 · 산출물 · 판단규칙 · 인계 · 컬러렌즈 · 자율도.

### A. 영업 AI (Sales) — 딜 구동 엔진
- **정의**: 핵심 판매 역할. 인바운드 리드 자격판정(SDR) → 딜 오너십 → 협상 → 클로징(AE). 유일한 매출(quota) 책임 역할. 베를로 특성상 **주로 인사이드 세일즈(원격: 메일/전화/화상)** 방식으로 수행하고, 필요 시 필드 미팅.
- **트리거**: 새 인입 스레드(고객·파트너·총판發 문의), 또는 마케팅 AI가 넘긴 MQL.
- **하는 일**:
  1. **자격판정**: 진짜 기회인가(ICP 적합) · 워크플로 분류(신규영업/리뉴얼/기술지원) · **상대 채널 역할 식별**(벤더/총판/파트너/고객)
  2. **딜 생성·단계관리**: opportunity 생성, stage 진행
  3. **견적 조율**: 총판 매입가 확보 → 고객 판매가 산정(영업지원·CFO와)
  4. **협상·클로징**: 가격·조건 협상, 수주
- **산출물**: 자격판정 결과, 딜(opportunity), 견적 방향, 다음 액션 제안
- **판단규칙**: 발신앵커(우리 응답 존재)=진행 근거 → 있으면 확신↑, 없으면 초기·미확정으로 보수 처리. 리뉴얼은 마진 20% 확인을 CFO와 교차.
- **인계**: 기술검토→프리세일즈, 구축/지원→엔지니어, 서류·견적문서→영업지원, 손익→CFO
- **컬러렌즈**: 🟠Orange(가치·마진) · 🔴Red(리스크) · ⚪Gray(자격 근거)
- **자율도**: 자격판정·딜초안·견적초안 자동 / **가격 결정·클로징은 사람**

### B. 영업지원 AI (Sales Support) — 행정·이네이블먼트
- **정의**: 비-quota. 딜을 굴러가게 하는 서류·기록·오더 처리. 영업의 행정 부담 제거.
- **트리거**: 영업가 넘긴 서류/등록/문서화 요청, 오더 처리.
- **하는 일**:
  1. **문서화**: 견적서·발주서·계약서 작성 (통합 저장소 GeneratedDocument)
  2. **등록/온보딩**: 파트너·총판·고객 등록(통장사본·인감·거래처등록·전자계약)
  3. **CRM 정합성**: 엔티티 dedup·연결·정리, 레코드 위생
  4. **후속**: 리마인더, 미회신 추적
  5. **문서 통합관리**: 버전관리·중앙보관
- **산출물**: 견적서 문서, 등록 완료, 정리·연결된 CRM 엔티티, 문서 버전
- **판단규칙**: 필수서류 체크리스트, 중복 엔티티 병합, **주소·사업자번호 검증**(예: `jm.lee@isd.co.kr` Undeliverable 바운스 감지→플래그)
- **인계**: 완료 딜→CFO 정산, 정리된 엔티티→전 역할 공용
- **컬러렌즈**: ⚪Gray(완결성·근거) · 🟢Teal(문서 명료성)
- **자율도**: 문서초안·기록·정리 자동 / **대외 발송·계약 확정은 사람**

### C. 프리세일즈 AI (Presales) — 제안·PoC
- **정의**: 기술 제안·PoC 설계·제품 적합성 판단.
- **트리거**: 영업가 넘긴 기술검토·제안 필요 딜.
- **하는 일**: 제안서 개요, PoC 시나리오·성공기준·일정, 제품↔요구 매핑, 경쟁 포지셔닝.
- **산출물**: 제안서(`generateDomainProposal`), PoC 계획서
- **판단규칙**: 과거 유사 딜 recall(DomainMemory), 제품 스펙 정확성, PoC 성공기준 측정가능성.
- **인계**: PoC 승인→엔지니어 구축
- **컬러렌즈**: 🔵Blue(기술 타당성) · ⚪Gray(근거) · 🟢Teal(명료성)
- **자율도**: 제안·PoC 초안 자동 / **고객 제출·PoC 착수 승인은 사람**

### D. 엔지니어 AI (Engineer / 기술지원) — 구축·지원
- **정의**: PoC 구축·납품·기술지원 티켓 처리.
- **트리거**: PoC 승인 / 기술지원 인입(파트너·고객發 장애·문의·조사표).
- **하는 일**: 구축 체크리스트, 납품 검수, **지원 티켓(파트너 SLA 1일/2일)**, 장애 대응·결과보고, 제품 조사표 대응.
- **산출물**: 구축 체크리스트, PoC 결과보고서, 지원 티켓·해결 기록
- **판단규칙**: **파트너 SLA(1일/2일)** 준수, 완료 기준(DoD), 재현·근본원인.
- **인계**: 납품완료→CFO 정산, 지원종결→기록/학습
- **컬러렌즈**: 🔵Blue(기술) · 🔴Red(일정·장애 리스크) · ⚪Gray(보고 완결성)
- **자율도**: 체크리스트·보고 초안 자동 / **고객 현장 대응·종결 판단은 사람**

### E. CFO / 재무 AI (Finance) — 정산·손익
- **정의**: 채널 손익·정산·세무.
- **트리거**: 딜 진행/완료, 세금계산서 수·발신, 입금.
- **하는 일**: **매입(총판)↔매출(고객) 손익**, 마진 실현 추적, 세금계산서 발행/수취, 입금 대사.
- **산출물**: 딜 손익, 마진 리포트, 정산 상태
- **판단규칙**: **리뉴얼 마진 20% 룰**(미만 경고), 매입≤매출 정합, 세금계산서 매칭.
- **인계**: 마진 경고·이상→영업
- **컬러렌즈**: 🟠Orange(마진) · 🔴Red(재무 리스크) · ⚪Gray(근거)
- **자율도**: 계산·집계·대사 자동 / **세금계산서 발행·지출 확정은 사람**

### F. 마케팅 AI (Marketing) — 수요 창출 [현재 미가동 / 향후]
- **정의**: 퍼널 최상단 demand gen. 인지·관심 창출, 리드(MQL) 생성.
- **현재 상태**: 베를로는 인바운드 반응형이라 마케팅 기능이 거의 없음. (v0에서 "마케팅"이라 부른 건 실은 위 A·B였다.)
- **향후 하는 일**: ① 아웃바운드 BDR(신규 파트너/고객/벤더 발굴, 콜드 아웃리치) ② 콘텐츠(제품 소개·구축 사례) ③ 채널 확장·시장 인텔 ④ 벤더(Sangfor) 공동 마케팅.
- **산출물**: 신규 리드(MQL), 아웃바운드 캠페인, 시장 리포트
- **인계**: MQL→영업 자격판정
- **컬러렌즈**: 🟠Orange(타겟 가치) · ⚪Gray(리드 근거)
- **자율도**: 리스트·콘텐츠 초안 자동 / **발송·집행은 사람**

## 4. 기존 코드 도메인 매핑 + 변경점

현재 GTM 도메인: `marketing · sales · presales · engineer · cfo`

| 기존 도메인 | v1 재정의 |
|---|---|
| `marketing` | **재정의 → demand gen(미가동)**. 기존이 하던 인입분류는 `sales`(영업)로 이동 |
| `sales` | **분리 → `sales`(영업: 판매 모션) + `sales_support`(영업지원: 행정)** |
| `presales` | 유지 (프리세일즈) |
| `engineer` | 유지 (구축·기술지원) |
| `cfo` | 유지 (재무) |

→ 도메인 상수/라우팅은 리플레이 엔진 반영 시 함께 조정. (본 문서는 설계; 코드 변경은 후속.)

## 5. 컬러렌즈 연계 (요약, 상세는 별도)

컬러렌즈는 이제 제안서만이 아니라 **모든 역할 AI 산출물**(자격판정·엔티티·견적·제안·보고)을 사람 전에 검증하는 일반 회의계층("회의적 기계"). 앵커(발신 증거) 있으면 관대, 없으면 회의적 기본값.
- 🔵Blue 기술 · 🔴Red 리스크 · 🟠Orange 가치/마진(리뉴얼 20% fail) · ⚪Gray 근거/완결성 · 🟢Teal 전달 명료성.

## 6. 리플레이 적용

시간순 643스레드를 통과: 영업 AI 자격판정·역할식별 → 해당 역할 AI 초안 → 컬러렌즈 검증 → 사람(대역) 발신앵커 기준 결정 → 학습. 채널·마진·타임라인이 살아있는 데이터로 축적.
