# U076 100건 실사용 검증 보고서

## 결론

서로 다른 가상 데이터 100건을 격리 PostgreSQL 환경에서 실제 제품 UI로 입력하고, 메일 학습·후보 생성·수동 검토·운영 레코드 생성까지 확인했다. 테스트 행과 인증 픽스처, 격리 Docker 컨테이너·네트워크·볼륨은 검증 후 모두 삭제했다. Grok 독립 교차검증 최종 판정은 PASS다.

## 입력 범위

| 채널 | 입력 방식 | 입력 수 | 확인 결과 |
|---|---|---:|---|
| 이메일 | 저장된 메일 다시 학습 UI | 50 | 메시지 50, 스레드 50, 후보 130 |
| 사용자 입력 | 새 회사 폼 입력·저장·상세 확인 | 50 | 고유 고객 50 |
| 합계 | 실제 UI 입력 | 100 | 입력 키 100/100 고유 |

100건은 입력 전수 검증 범위다. 승인·반려·AI 재검증·유형 교정·연결은 각 기능 경로의 대표 후보를 실제 클릭해 산출물과 감사 로그를 확인한 샘플 검증이며, 130개 후보 전수 승인 또는 전수 변환을 뜻하지 않는다.

## 실제 기능 경로

- 메일 50건 학습 후 수신함에서 후보 130건을 확인했다.
- 고객 후보 승인·생성 결과의 회사명과 도메인을 원본 입력과 exact-match로 확인했다.
- 후보 반려와 `weak_evidence` 사유 저장을 확인했다.
- 프로젝트성 후보의 AI 재검증 후 업무 레코드 생성을 확인했다.
- 고객 후보를 파트너로 교정한 뒤 파트너 레코드 연결을 확인했다.
- 애플리케이션 DB 역할과 프로젝트 GUC를 사용해 후보 130건, 직접 입력 고객 50건의 RLS 가시성을 확인했다.

## 발견 및 수정

1. 수동 액션 UI에 CAS 버전과 멱등 키가 빠진 호출부를 모두 보완했다.
2. 인증·스코프·CAS 없이 상태를 바꾸던 배치 HTTP 경로를 인증 후 `410 Gone`으로 폐기하고 OpenAPI에서 제거했다.
3. 비스코프 레거시 거부·유형수정·배치 비즈니스 함수를 제거했다.
4. 제안 상태 고객·파트너 승인과 변환을 하나의 원자 경로로 연결했다.
5. 메일 후보 RLS 정책을 메일 스레드 또는 지식 문서의 프로젝트 계보로 복구했다.
6. AI 감사 JSON의 `undefined` 값이 RFC 8785 정규화를 깨뜨리던 문제를 수정했다.
7. 다중 라벨 테스트 도메인이 회사명 `Example`로 잘못 변환되던 문제와 `Re` 접두 회사명 오탐을 수정했다.
8. 연결 UI를 실제 동작인 “후보 유형별 운영 레코드 1건”으로 정정했다.

## 삭제 검증

- 테스트 메일, 스레드, 후보, 직접 입력 고객, 생성된 고객·파트너·업무를 모두 0건으로 정리했다.
- 삭제 후 고객 화면에는 기존 격리 픽스처 1건만, 수신함에는 대기 후보 0건만 표시되는 것을 Aside CLI 화면으로 재확인했다.
- 세션 JWT가 있던 `fixtures/storage-state`와 런타임 자격정보 파일을 삭제했다.
- 격리 Docker 리소스는 `remainingLabelCount=0`이며 이름·라벨 일치 컨테이너, 네트워크, 볼륨이 남지 않았다.
