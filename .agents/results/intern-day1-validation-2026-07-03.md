# 출근 1일차 인턴 페르소나 실검증 (2026-07-03)

프로덕션 빌드(web:3105 ↔ api:3210, JWT 인증 활성) 기준. "URL만 전달받은 신입"이 실제로 겪는 여정을 브라우저 상호작용 + 스크린샷으로 검증.

## 여정 시나리오와 결과

| 단계 | 시나리오 | 결과 |
|---|---|---|
| 1 | 비로그인 첫 접속 (`/` → `/dashboard`) | ❌ **BLOCKER**: "HTTP 401: Unauthorized" 기술 문구만 표시, 로그인 안내 0개 |
| 2 | 로그인 페이지 찾기 (`/login`, `/auth/login`) | ❌ **BLOCKER**: 둘 다 404 — 로그인 UI 자체가 없음 (API로만 존재) |
| 3 | 로그인 후 `/home` | ✅ 영업 대시보드 정상 (KPI/파이프라인/최근 딜/위험) |
| 4 | 사이드바 탐색 (내 업무/작업/회사/지식/설정) | ✅ 전부 정상 렌더. 핵심 8메뉴 + "더보기(26)" 구조는 신입에게 적절한 점진 공개 |
| 5 | `/my-work` 첫 랜딩 | ✅ 영업기회·작업·제안서·PoC 통합 뷰 — 인턴 시작점으로 우수 |
| 6 | 작업 생성 + 빈 폼 제출 (실수 시나리오) | ✅ "작업 추가" 폼 존재, 빈 제출 시 브라우저 네이티브 검증("Please fill out this field") 동작 |
| 7 | 설정 화면 | ✅ LLM 키 마스킹 표시 정상 (P16 unwrap 수정의 실화면 검증) |
| 8 | 막혔을 때 도움말 찾기 | ⚠️ 홈에 도움말/가이드/온보딩 요소 0개 (메뉴 검색만 존재) |

## 수정 완료 (이 브랜치)

1. **`/login` 페이지 신설** (`apps/web/src/app/login/page.tsx`) — 이메일(선택)+비밀번호 폼 → `POST /api/auth/login` → 세션 쿠키 → `/home`. 401/429/네트워크 에러별 한국어 안내.
2. **대시보드 401 에러 카드 개선** (`executive-dashboard.tsx`) — 401이면 "로그인이 필요합니다 / 세션이 없거나 만료되었습니다" + "로그인하러 가기" 버튼.

재검증(E2E 실클릭): 비로그인 접속 → 안내 확인 → 클릭 → 폼 입력 → 홈 도착 + 오입력 시 "비밀번호가 올바르지 않습니다." 표시 — 통과, 페이지 에러 0.

## 남은 개선 제안 (미수정 — 별도 결정 필요)

- **온보딩/도움말 부재**: 첫 로그인 시 투어·가이드 없음. 인턴은 "내 업무"를 스스로 발견해야 함.
- **다른 대시보드들의 401 처리**: sales/presales/support/delivery/my-work/mail-intelligence의 ErrorState도 동일 패턴 적용 가능 (이번엔 첫 화면인 executive만 수정).
- **비로그인 상태 우상단 "Portal Operator" 표시**: 로그인 안 했는데 운영자로 보임 — 세션 기반 표시로 교체 검토.
- 빈 폼 검증이 영어 브라우저 네이티브 메시지 — 한국어 커스텀 검증 메시지 검토.
